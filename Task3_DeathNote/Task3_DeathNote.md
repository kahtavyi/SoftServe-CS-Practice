# Death Note

### https://www.vulnhub.com/entry/deathnote-1,739/

---

### 1. Розвідка мережі та сканування портів

Спочатку визначаємо IP-адресу цільової машини в локальній мережі:

```
sudo netdiscover -r 10.0.2.0/24
```

Далі скануємо знайдену ціль:

```
nmap -Pn -sV 192.168.56.102
```

- Параметр `-Pn` вимикає ping-перевірку — `nmap` не буде перевіряти, чи «жива» ціль, за допомогою ping/SYN-запитів. Це корисно, коли хост фільтрує ICMP.
- Параметр `-sV` визначає версії служб, що працюють на відкритих портах.
- Результат сканування: відкрито два порти — **22 (SSH)** та **80 (HTTP)**.
- Брутфорсити SSH одразу немає сенсу — немає ані логіну, ані пароля, тому спочатку досліджуємо веб-сервіс на 80 порту.

### 2. Перше звернення до веб-сервера

Відкриваємо `http://192.168.56.102` у браузері — сторінка повертає помилку, але в ній міститься підказка у вигляді доменного імені **deathnote.vuln**. Це означає, що застосунок очікує звернення саме за цим іменем (Virtual Host), а не за «голою» IP-адресою.

![помилка на 80 порту з підказкою на deathnote.vuln](screenshots/Screenshot%20From%202026-08-02%2011-43-09.png)

---

### 3. Прописуємо hosts-файл

Щоб браузер міг зарезолвити ім'я `deathnote.vuln` в IP-адресу цілі, редагуємо локальний файл hosts:

```
sudo nano /etc/hosts
```

Додаємо рядок:

```
192.168.56.102 deathnote.vuln
```

![редагування /etc/hosts](screenshots/Screenshot%20From%202026-08-02%2011-43-38.png)

### 4. Дослідження сайту

Після повторного відкриття `http://deathnote.vuln/` переглядаємо вихідний HTML-код сторінки та знаходимо посилання на директорію із зображеннями, у назвах яких зустрічається слово **kira**.

![перегляд коду сторінки, посилання на директорію з kira-файлами](screenshots/Screenshot%20From%202026-08-02%2011-45-25.png)

Переходимо за цим шляхом і бачимо перелік файлів, серед яких — два текстові файли з іменами **notes** та **user**.

![директорія з файлами kira, notes.txt, user.txt](screenshots/Screenshot%20From%202026-08-02%2011-46-13.png)

### 5. Сканування директорій та файлів сайту

Для пошуку прихованих директорій і файлів використовуємо:

```
dirsearch -u http://deathnote.vuln/
```

(за відсутності — встановлюємо: `sudo apt install dirsearch`, або користуємось аналогами `dirb`/`gobuster`)

- Параметр `-u` вказує URL сайту, на якому виконується brute-force каталогів і файлів.

Скан знаходить, зокрема:

```
/robots.txt
/wordpress/wp-login.php
```

![результат dirsearch](screenshots/Screenshot%20From%202026-08-02%2011-46-27.png)

### 6. robots.txt → important.jpg → приховані файли

На сторінці `/robots.txt` міститься текст із вказівкою перейти на `/important.jpg`. Пряме відкриття файлу в браузері нічого не показує, тож звертаємось до нього через `curl`:

```
curl http://deathnote.vuln/important.jpg
```

У відповіді сервера згадуються файли **user.txt** (схоже на ідентифікатор/логін) і **notes.txt** (схоже на список можливих паролів). Каталог, у якому вони лежать, вже відомий з кроку 4 (директорія з "kira").

![curl important.jpg → згадки user.txt / notes.txt](screenshots/Screenshot%20From%202026-08-02%2011-54-16.png)

Переходимо у знайдену директорію та зберігаємо собі файли **user.txt** і **notes.txt** для подальшого брутфорсу.

![завантаження user.txt та notes.txt](screenshots/Screenshot%20From%202026-08-02%2011-57-03.png)

### 7. Брутфорс SSH-доступу (hydra)

Маючи потенційний список логінів (`user.txt`) та паролів (`notes.txt`), запускаємо перебір облікових даних для SSH:

```
hydra -L user.txt -P notes.txt 192.168.56.102 ssh
```

- Параметр `-L` вказує файл зі списком логінів.
- Параметр `-P` вказує файл зі списком паролів.

У результаті отримуємо робочу пару логін/пароль для SSH-з'єднання.

![hydra знайшла валідні креденшели](screenshots/Screenshot%20From%202026-08-02%2012-03-27.png)

### 8. Вхід по SSH та розшифрування нотатки

Підключаємось до цілі з отриманими обліковими даними:

```
ssh l@192.168.56.102
```

![успішний вхід по SSH](screenshots/Screenshot%20From%202026-08-02%2012-04-22.png)

У домашньому каталозі користувача знаходимо файл `user.txt`, вміст якого записаний мовою езотеричного програмування **Brainfuck**. Розшифровуємо його за допомогою онлайн-декодера (наприклад, `dcode.fr`) і отримуємо текстове повідомлення від «Кіра» з натяком, що доступ до shell отримано, але це ще не перемога.

![вміст user.txt у форматі brainfuck та його розшифровка](screenshots/Screenshot%20From%202026-08-02%2012-11-07.png)

### 9. Пошук слідів "kira" у файловій системі

Шукаємо по всій файловій системі файли й каталоги, що містять у назві слово **kira**:

```
find / -iname "*kira*" 2>/dev/null
```

![пошук файлів/директорій з "kira" у назві](screenshots/Screenshot%20From%202026-08-02%2012-12-49.png)

Переміщуємось у знайдений каталог:

```
cd /opt/kira-case
```

і переглядаємо файл `case-file.txt`, у якому міститься підказка, що щось цікаве приховано в каталозі **fake-notebook-rule**.

![case-file.txt із підказкою на fake-notebook-rule](screenshots/Screenshot%20From%202026-08-02%2012-18-20.png)

Там знаходимо аудіофайл `case.wav`. Прослухавши/декодувавши його (закодована азбука Морзе / службовий сигнал), отримуємо пароль у відкритому вигляді:

```
password: kiraisevil
```

![декодування case.wav → пароль](screenshots/Screenshot%20From%202026-08-02%2012-20-11.png)

### 10. Підвищення привілеїв: користувач kira → root

Переходимо на користувача **kira** з отриманим паролем:

```
su kira
```

> Команда `su` використовується для зміни поточного користувача сесії.

![перехід на користувача kira](screenshots/Screenshot%20From%202026-08-02%2012-21-11.png)

Перевіряємо, чи підходить той самий пароль для отримання прав суперкористувача:

```
sudo -i
```

Вхід виконано успішно. Переходимо в `/root` та переглядаємо вміст каталогу:

```
cd /root
ls
cat root.txt
```

Отримуємо фінальний прапор **root.txt** — машину Death Note повністю пройдено (user + root).

![отримання root-доступу та root.txt](screenshots/Screenshot%20From%202026-08-02%2012-24-01.png)

| Етап | Техніка / інструмент | Результат |
|---|---|---|
| Розвідка | `netdiscover`, `nmap -Pn -sV` | Знайдено хост, відкриті порти 22, 80 |
| Резолвінг імені | редагування `/etc/hosts` | Доступ до вірт. хосту `deathnote.vuln` |

| Збір даних | `curl`, ручний перегляд файлів | Отримано `user.txt`, `notes.txt` |
| Брутфорс | `hydra` (SSH) | Отримано пару логін/пароль |
| Доступ user | `ssh` | Shell від імені користувача `l` |
| Аналіз | декодування Brainfuck, Morse/аудіо | Отримано пароль `kiraisevil` |
| Ескалація | `su kira` → `sudo -i` | Отримано root-доступ, прапор `root.txt` |
