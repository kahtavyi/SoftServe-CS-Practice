## 1. Мережева розвідка (Reconnaissance)

Першим кроком було визначення IP-адреси цільової машини в ізольованій локальній мережі за допомогою утиліти `arp-scan` (як альтернатива `netdiscover`).

![arp-scan](images/Screenshot%20From%202026-08-02%2015-22-47.png)

> **Контрольне питання:** Яка з команд буде працювати швидше: `sudo netdiscover` чи `sudo netdiscover -r 10.0.2.0/24`?
> **Відповідь:** Швидше відпрацює `sudo netdiscover -r 10.0.2.0/24`. Якщо запустити утиліту без вказання діапазону, вона автоматично скануватиме всі стандартні приватні підмережі (класів A, B, C), що займає багато часу. Вказуючи конкретну маску (`-r`), ми жорстко обмежуємо сканування однією підмережею на 256 адрес, що виконується майже миттєво.

Після виявлення IP-адреси цілі, було проведено сканування портів за допомогою `nmap` для визначення активних сервісів.

![nmap scan](images/Screenshot%20From%202026-08-02%2015-26-18.png)

> **Контрольне питання:** В чому різниця між командами `sudo nmap -A --reason <IP>` та `sudo nmap -sV --reason <IP>`? 
> **Відповідь:** 
> *   Прапорець `-sV` фокусується виключно на визначенні версій сервісів, які працюють на відкритих портах. Це швидший і менш "галасливий" варіант сканування.
> *   Прапорець `-A` (Aggressive) — це комплексний параметр, який включає одразу декілька етапів: визначення версій сервісів (`-sV`), визначення операційної системи (`-O`), виконання стандартних скриптів Nmap (`-sC`) та трасування маршруту (`--traceroute`). Відповідно, команда `-A` дає значно більше інформації, але виконується відчутно довше.

*Сканування показало, що відкритий лише порт 80 (HTTP), на якому працює вебсервер Apache з CMS WordPress.*

Перевірка порту 80 у браузері підтвердила наявність сайту на базі WordPress.

![Вебсайт головна](images/Screenshot%20From%202026-08-02%2015-28-23.png)

## 3. Отримання початкового доступу (Initial Access)

Маючи імена користувачів, було проведено атаку методом перебору (Brute-force) на панель авторизації WordPress за допомогою утиліти `wpscan` та словника `rockyou.txt`.

![wpscan bruteforce](images/Screenshot%20From%202026-08-02%2016-48-22.png)

Атака пройшла успішно, отримано валідні облікові дані для доступу в адмін-панель. Після входу в систему (`/wp-admin`) було використано вразливість редагування тем.

![wp-admin login](images/Screenshot%20From%202026-08-02%2017-58-07.png)

У редакторі тем один із PHP-файлів було замінено на код `php-reverse-shell`. На атакуючій машині запущено слухача `netcat` (`nc -lvnp`). Після звернення до зміненого файлу через браузер, було успішно отримано зворотну оболонку (Reverse Shell) від імені користувача `www-data`.

![Theme editor payload](images/Screenshot%20From%202026-08-02%2018-35-49.png)
![Reverse shell catch](images/Screenshot%20From%202026-08-02%2018-42-40.png)

## 4. Горизонтальне підвищення привілеїв (User Flag)

Отримавши доступ до системи, було досліджено файли конфігурації вебсайту. У файлі `wp-config.php` знайдено пароль для бази даних, який також підійшов для системного користувача `c0ldd`.

![wp-config.php password](images/Screenshot%20From%202026-08-02%2018-44-51.png)

Використано команду `su c0ldd` для перемикання на цього користувача. 

![su c0ldd](images/Screenshot%20From%202026-08-02%2018-46-31.png)

У домашній директорії знайдено файл `user.txt`. Вміст файлу був зашифрований у Base64. Після декодування отримано перший прапор.

![cat user.txt](images/Screenshot%20From%202026-08-02%2018-47-09.png)
![Base64 decode user](images/Screenshot%20From%202026-08-02%2018-48-28.png)

## 5. Вертикальне підвищення привілеїв (Root Flag)

Для подальшого підвищення прав було перевірено дозволи `sudo` для користувача `c0ldd` за допомогою команди `sudo -l`.

![sudo -l](images/Screenshot%20From%202026-08-02%2018-57-35.png)

Перевірка показала, що користувач має право виконувати певні бінарні файли (наприклад, `chmod`, `vim`, `ftp`) від імені суперкористувача без введення пароля. Використовуючи інструкції з ресурсу GTFOBins, було успішно проексплуатовано один із цих бінарників для отримання оболонки `root`.

![Privesc execution](images/Screenshot%20From%202026-08-02%2018-58-55.png)

Отримано доступ до директорії `/root` та успішно прочитано фінальний прапор `root.txt`. 

![Root flag](images/Screenshot%20From%202026-08-02%2018-59-46.png)
